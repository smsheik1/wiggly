You are the operating agent. Read requirements.json, scene-contract.json and quality.json. Use this package's runner.mjs; never rebuild its state machine or invoke the old app scripts. Install pinned dependencies with `npm ci`, then run `npm run check` and `npm run smoke`. Use a new absolute run directory, separate from legacy runs. Existing checkpoints cannot be reset by init.

```sh
node runner.mjs init examples/parent.json --run /absolute/new-run
node runner.mjs status --run /absolute/new-run
node runner.mjs work --run /absolute/new-run
node runner.mjs schema script
node runner.mjs schema event
node runner.mjs respond /absolute/event.json --run /absolute/new-run
```

# Stage sequence and production tools

1. **Script:** Elevate memories into clear, skilled storytelling children understand, with four 15-second narration windows and an emotional purpose per beat. This is narration over memories. No v1 dialogue/lip-sync requirement. Preserve facts and meaning, not weak storytelling. Check important people, age variants, reference availability, settings, props and difficult actions before script lock. Missing source facts require clarification; no invented autobiographical claims.
2. **Voice sample and clone:** After script approval, obtain a genuine storyteller sample and consent. Use `import /absolute/sample.wav --run ...`; put its returned file record in the `voiceSample` human artifact with `consent: true` and language, using the actual user. At least 10 measured seconds; clean, single-speaker speech is required. Cartesia uploads must be WAV/MP3/FLAC/OGG under 16 MB. Convert other formats locally without tempo changes. Submit the current authorized clone request, then review its audition against the actual sample; human approval follows. No stock/Trevor voice. Optional Gemini needs an explicit user request and separately verified adapter; this version stops rather than silently switching.
3. **Narration:** Generate the locked four beat texts separately with the current cloned voice and speed 1. Measure and directly listen. Use `measure narration` for ffprobe duration and ffmpeg silence; a capable review worker must also run STT, compare words with the locked script, measure rate and speaker similarity against the actual sample, and explain calibration and limitations. Both audition and narration approval require these measurements plus direct audio perception. No automatic similarity threshold is claimed. Overlong narration must return to the writer; do not speed audio or trim words. A rejected audio review with `repairTarget: "script"` escalates for a script change instead of wasting another generation. If text must change, obtain human agreement via script `changes`; its dependent audio locks reopen. The current narration deliverable is reviewed/approved as a four-file set; per-beat regeneration and approval events are future refinement.
4. **Roster:** Only after audio lock, establish every important character and age variant. Import actual reference images and include their returned file records per roster entry. The reviewer verifies completeness before human approval.
5. **Characters:** Produce three reference-conditioned Muse candidate designs per roster entry. Agent review then human selection. The host author reads the selected image and character-sheet-recipe.md, writes the full sheet prompt and records both source hashes. Use `node runner.mjs recipe` for the packaged recipe hash. Prompt review then sheet generation MUST send the selected image. Require four full-body turnaround views and eight expressions, consistent identity/anatomy/outfit. Expression names are explicit in the authored prompt; the tutorial's angry-vs-determined choice remains a design question rather than a hidden substitution. Sheet reviewer then human approval; repeat for EVERY roster character. Additional age variants are separate entries. Then establish the background registry.

6. **Background registry (`backgrounds`):** The background product owner establishes scene IDs, beat assignment, immediate scene descriptions/actions, known cast IDs, locations and needed angle IDs. Cover all four beats; do not force one location per beat. Establish only angles the scenes need. Independent review and human approval lock the registry.
7. **One location at a time:** At `backgroundBrief`, the owner writes ordinary human direction, not an image-model prompt. The task gives immediate scenes first, the approved script next, questionnaire supporting only. Record known/proposed details, staging space, continuity and optional imported reference files. Ordinary furnishings may be proposed; missing emotionally important facts require user clarification through an inconclusive review/escalation. A bank reference is inspiration, not a factual place; record that distinction in the direction/proposed details. No bank is bundled. Reviewer and human approve the brief.
8. **Separate prompter:** At `backgroundPrompt`, a different actual worker uses the packaged background-prompter.md (scoped from the user’s Dan Kieft MD). `work` includes its content/hash; `background-recipe` prints it separately. Return full prompt, briefDigest, recipeSha256 and changeSummary. At `owner-review`, the original brief author returns an `owner-review` event with `actor: "agent"`, exact artifact ID/digest and the normal complete evidenced Review. Owner pass → a third independent reviewer → explicit human prompt approval. Rejections return to the prompter and repeat the owner check; repeated disagreement or missing perception escalates. Workers are host roles, not permanently provisioned machines. IDs are bindings, not proof of genuine worker independence.
9. **Master background:** `backgroundCandidates` permits exactly the human-approved prompt, three Muse images and $0.03 minimum estimate. With no supplied references the adapter calls generations; with references it calls edits and sends their real bytes. Empty environments, stylised 3D style, scene/action fit and continuity must be directly reviewed. Human `approve` selects index 0–2 and locks that location’s master. Inspect every candidate internally; do not present defective candidates as options.
10. **Required angles:** For each registry angle: `backgroundAngleBrief` owner human-language direction → independent review/human → `backgroundAnglePrompt` separate prompter → original owner check → independent review/human → `backgroundAngle` one Muse image using the actual selected master bytes → direct image review/human. Preserve geography and furnishings. Unseen geography is a proposal, never assumed proven 3D continuity. Finish every angle before the next location. Once all are locked, proceed to `shots`. All visual locks remain required before video.

11. **Shot plan (`shots`):** The host shot planner reads immediate scenes, approved script/narration, actual approved location references and character sheets supplied by `work`. Plan ordered shots covering each beat's local 0–15 second timeline exactly, without gaps or overlaps. Cover every established scene; bind its exact location/approved master or angle, cast/age variants, camera, action, staging and continuity notes. Reviewer then human approval. Multiple shots may serve one beat; there is no fixed shots-per-beat count. These timings plan the final edit, not a video model's generation duration. Do not impose an unverified five-second video-model law or accelerate narration.
12. **Composition prompt (`keyframePrompt:<shotId>`):** Write the full single-frame prompt. `work` supplies the shot, `shotDigest`, actual ordered reference images and `referenceBindings`. Return `prompt`, `shotDigest` and `references` exactly matching those bindings. The first image controls the setting geography; the remaining approved sheets control each character's identity, age, scale and wardrobe. Describe camera, placement, eyelines, anatomy, prop ownership/contact, emotional acting and lighting. Restate only necessary design anchors; do not overwrite image identities with prose or transfer a room reference's people. Do not generate a storyboard collage, crop or thumbnail. Independent text review → explicit human prompt approval.
13. **Keyframe (`keyframe:<shotId>`):** The runner accepts only the approved prompt and snapshots one Muse edit with the actual selected setting and every required character-sheet image in the bound order. Minimum estimated cost $0.01. Existing exact authorization/bounded image allowance rules apply. Returned media must be measured 16:9, at least 1280×720, and directly reviewed for scene fit, identity, anatomy, setting continuity, staging, style and composition. File validity is not creative approval. Extra hands, wrong face/age, floating props and unusable staging require localized rejection/repair, not a passing result shown to the user. A usable frame then pauses for explicit human approval. Repeat for every planned shot, then proceed to `reviewerQualification/author`.

14. **Visual reviewer qualification:** This is a pre-video capability gate, independent of story assets. A worker cannot submit its own qualification artifact. Build a separate actual human-labelled corpus: `VisualCase` records in evaluation/visual-qualification.mjs, with imported immutable image/video files, group/split, criterion, relevant reference files and localized human label/repair. Identity/continuity cases require independent reference media. Do not use synthetic test labels in production. Freeze holdout before tuning; keep a source run and its derivatives together; references also cannot leak across splits. Each image/video × anatomy/identity/continuity scope needs at least two distinct usable and two distinct broken held-out examples, all correctly classified with direct perception. Shared files do not increase coverage within a criterion. This is a conservative v1 acceptance policy, not statistical proof of perfection. Known anatomy labels alone are insufficient for identity/continuity.

```sh
node runner.mjs visual-tasks --dataset /absolute/visual-cases.json --split holdout
node runner.mjs qualify-visual --dataset /absolute/visual-cases.json --predictions /absolute/worker-predictions.json --worker actual-reviewer --model actual-model-version --run /absolute/new-run
```

`visual-tasks` withholds labels/split/group. Obtain actual predictions from the independent host worker with case ID/input digest, worker/model, direct-image/direct-video perception and a localized check. `qualify-visual` verifies the actual media, evaluates held-out predictions, saves local evidence and creates the runtime-only report when both scopes pass. The report exposes evidenceDirectory containing dataset.json/predictions.json/report.json. These sources are saved before review and recomputed/verified before approval/generation/finalization; deleting them blocks advancement. Separate report review then human approval. Empty/sparse coverage, missed defects, false rejections, unavailable perception or mismatched predictions cannot qualify. The seed evaluation dataset does not meet this requirement. Model/prompt/capability changes require new qualification via human changes to this artifact; it invalidates dependent videos. This remains a trusted local protocol: IDs and human label declarations are not cryptographic worker authentication.
15. **Motion plan (`videoPlan`):** Motion director splits each approved shot into clips with unique IDs, shot ID, local start, edit duration, integer model duration, camera/action/anchors/atmosphere. Complete each shot at frame-aligned 30fps edit boundaries with no gaps/overlaps; keep all four 15-second beat timings. Five-second clips are a conservative starting point. Seedance's documented 4–15 second duration range is supported; no invented rule claims quality collapses after six seconds. Reviewer → human plan approval.
16. **Video prompt and generation:** Video engineer binds exact clip digest, keyframe ID/hash and concise observable motion, contacts, camera and environment. `work` provides these bindings. Independent review → human prompt approval → positive account-verified cost estimate → exact human request authorization → Replicate Seedance 2.0 I2V. The adapter uploads actual approved keyframe bytes, requests 1080p/16:9 and disables generated audio. No text-only image identity claims or silent alternate model. `generate` POSTs once; a pending prediction stays at collect. `collect` polls that same ID once per invocation and downloads a completed result; rerun collect as appropriate, never regenerate a started request. API failure stops for reconciliation. Short clips and physical anchors are prompting choices, not anatomy guarantees.
17. **Full video review:** The qualified worker ID/model must match the qualification report and review the entire current file, binding its hash and viewed duration. Frame thumbnails alone cannot approve motion. Inspect anatomy (including extra hands), identity/age, geography/prop contacts, temporal drift, usable action and integrity against approved references. Every failed criterion needs time-localized evidence and repair. Failures remain internal; first rejection reopens the clip prompt, not a user presentation of defective video. Approve repaired prompt again, then obtain exact authorization or use an explicit bounded technical-repair allowance. Both passing and rejected direct video/film judgments must match the qualified worker/model and hash/coverage; unavailable perception is inconclusive, not a paid-repair trigger. A second rejection escalates to the user without presenting it as a usable deliverable. Passing video then human approval; repeat each clip. Still-valid other clips are retained.
18. **Sound plan:** After video locks, sound designer directs a 60-second instrumental acoustic piano score and only story-serving timed effects. Each may be generated through the explicit ElevenLabs adapter or imported as measured local audio. Specify provenance/source/usageRights, mode and cue timing/gain; explain if no effects. Reviewer → human approval. Generated music uses music_v2_5 with force_instrumental and 60000ms; effects use eleven_text_to_sound_v2, duration and no loop. Positive account-verified estimates and ordinary exact paid authorization/explicit bounded sound allowances apply. No key is needed for imports. Each actual music/effect asset must cover its planned duration and receives direct listening review and human approval. Provider metadata cannot establish piano instrumentation, no vocals, appropriateness or licensing.
19. **Edit plan:** Film editor binds every approved clip in order with source trim offsets, narration/music/effect gains, piano ducking/fades and explicit natural pauses per beat. Reviewer → human approval. Do not speed voice, clip speech or swap voices. Edits and final film depend on all current clips/sound/narration. Changing one clip invalidates its edit and film while preserving unrelated clips/sound. Changing the sound plan conservatively reopens all sound assets; finer per-cue invalidation is a future refinement.
20. **Official local assembly and final review:** At film/produce, run `node runner.mjs render --run ...`. FFmpeg prepares one natural-rate mixed audio track with narration at 0/15/30/45 seconds, piano ducking/fades and cues. Remotion renders the exact approved clips through `RemotionAdScene → AdRenderSurface → memoir-film` at 60s 1920×1080 30fps H.264/AAC. Source trim offsets must align to the 30fps frame grid. `node runner.mjs preview --run ...` serves a private localhost Remotion Player using the same scene and audio; leave the process running while reviewing it. Preview changes no approvals and submits no provider calls. The archive ships the compiled official renderer with a checked inventory. Missing/changed bundles stop; there is no FFmpeg video-assembly fallback. Run-folder assembly progress.json/progress.html track progress; a contact sheet is supporting evidence. Duration/dimensions/frame rate/audio and actual loudness (-18 to -14 LUFS, ≤-1dB true peak) are technical gates; long black regions reject. Freeze measurements are advisory: the reviewer must distinguish intentional holds from broken motion. The qualified reviewer inspects the full actual video and audio (hash + video/audio durations), gives every final criterion evidence, and returns only usable work to the human. A rejected film returns localized repair to editPlan by default. Use review.repairArtifactId to target a current used video/keyframe/music/effect artifact; its dependent edit/film reopen while unrelated work remains valid. A narration-source repairArtifactId is accepted but escalates before rebuilding: in this v1 model it reopens downstream visuals as well as the edit. Run impact and obtain explicit human direction; the locked script/clone remain valid. Human final-film changes reopen the editor by default. A repeated failed-film review escalates. After human final-film approval, `finalize` verifies current dependencies and media again and writes a private finalized.json manifest with film path and provenance. It does not publish/share/upload. No actual final movie or end-to-end production quality was proven during this implementation.

Rejected keyframes return localized findings to the composition writer; prompt approval is required again before a repair request. Human changes to a keyframe reopen its prompt. The three-request generation ceiling counts all attempts for a shot under the same approved shot-plan version, even when its prompt changes. Repeated-review escalation and exact request recovery still apply. The retry policy is conservative v1 orchestration, not an automatic visual judge.
