# My Pixar Story — LangGraph Format runtime v2.0.0

A portable, agent-operated Wiggly Format for turning a loved one's memories into a planned 60-second theatrical 3D animated memoir: four 15-second beats, their own cloned narration, widescreen imagery, acoustic piano and cinematic lighting.

**Current checkpoint: implemented workflow through final-film approval and local finalization.** This is tested orchestration, not a production-proven animation studio. New runs use human-supervised review without pretending reviewers are qualified. Actual perception and evidenced agent review precede explicit human media confirmation; every video request requires exact human authorization. Deliberately selected qualified-mode runs retain the stricter held-out gates. No reviewer is currently qualified; real end-to-end production proof was explicitly excluded.

Read **SKILL.md** to operate it. Install with `npm ci`; run `npm run check`, `npm test` and `npm run smoke`. No Wiggly application checkout or cloud database is required. The package uses embedded SQLite for LangGraph checkpoints and direct hosted-provider APIs. No ComfyUI, local AI models, Antigravity dependency or additional chat-agent framework.

The operating host agent writes and reviews artifacts. LangGraph controls saved state, approval pauses and legal transitions. `work` exposes the next structured task; a configured host adapter can automate one task through the scoped format tool broker. A custom host supplies its actual worker/model bindings; the shipped native Codex crew defaults to GPT 5.6 Sol through studio.json. Gemini supplies the shipped native audio/video perception adapter behind explicit call caps and account estimates; custom hosts may supply compatible perception tools. This package does not launch guessed host CLI commands.

New supervised projects now review and human-confirm existing questionnaire answers before script writing (ANSWERS LOCK). Cleo authors a reference-bound character prompt, Sage reviews it and the human approves before any candidate call. Old saved revision-2 projects keep their current sequence without migration.

Cartesia is the default voice-clone/TTS path; Muse uses actual reference images for three candidates and the selected character's standardized sheet. No stock voice or text-only identity fallback. The current provider adapters are documentation-checked and tested with isolated HTTP mocks; no real clone, narration or image generation was performed for this implementation.

Tests demonstrate persistence, typed transitions, review/approval loops, file hashing, natural-speed requests, reference transmission and request recovery. They do not prove voice likeness, animation quality, reliable defect perception or commercial readiness. Local Codex dispatch now connects independent Cartesia batch STT behind an explicit call cap; a calibrated speaker embedding tool remains unprovided. Missing measurements keep review inconclusive.

The archive includes pinned dependencies, contracts, recipes, two questionnaire examples, official runner and free tests. It excludes secrets, installed dependencies, run checkpoints and prior celebrity outputs. The canonical evolving design remains Wiggly's `docs/memoir-system-living-spec.md`; this README is operational status, not another master design.

The evaluator foundation adds `npm run eval` and `npm run eval:holdout`, a data-first collection of 22 scoped cases with 145 asset provenance records, labelled prediction comparison, and a local LangSmith-ready export. The baseline honestly reports the known extra-hand clip as unresolved/missed: no autonomous anatomy judge is connected. See `evaluation/README.md` for commands, split policy, results and remaining human-label needs. Existing reviewer tasks receive advisory contract/audio evidence, never automatic approval.

Backgrounds run one location at a time: scene registry → owner’s plain-language brief → separate Pixar Markdown prompter → owner check → independent review → human prompt approval → three Muse concepts → actual image review → human master selection → separately approved additional-angle prompts and reference-conditioned images. The owner’s brief also receives review and human approval in v1. All character sheets and audio must remain locked. See the background stages in SKILL.md. No setting-reference bank is shipped yet.

Scene composition now plans ordered shots across four locked 15-second beats, then loops through a bound composition prompt, independent review, human approval, one reference-conditioned Muse keyframe, actual image review and human approval per shot. The adapter sends the selected setting and all cast sheets as real reference bytes. Repairs reopen the affected prompt; background revisions preserve other locations’ frames. Supervised video follows actual advisory review/human locks and exact spending approval; qualified mode additionally needs reviewer qualification. Free tests demonstrate these contracts; no paid keyframes or production-quality visual judge were proven.

The finishing stages now include a per-clip motion plan/prompt, the direct Replicate Seedance 2.0 Mini adapter at 480p for new projects (saved legacy profiles unchanged), full-video review and bounded technical repair, an explicitly reviewed narration-only finish by default, with optional piano/effects via ElevenLabs generation or licensed imports, an approved edit plan, one shared Remotion composition through Wiggly’s AdRenderSurface and final audiovisual review. Four 15-second beats stay fixed while shorter clips cover each shot. Natural-rate narration is preserved at 0/15/30/45 seconds. New supervised projects append silence to create four exact 15.0-second windows, retain originals/hold durations, and calculate speech rate before padding. Overlong speech is never shortened or accelerated; it returns to script repair and approval. FFmpeg prepares the shared audio mix; Remotion renders the approved clip timeline. Local assembly records progress, measured loudness/peak/black/freeze signals and asset provenance. `finalize` checks current approval/hash/timing and writes a private local manifest; it does not publish.

Qualification tests use explicitly isolated synthetic fixtures to test mechanics, never to certify a judge. The operating host must supply genuinely independent perceptual workers, measured STT/speaker comparison and human-adjudicated visual examples. Qualification is a pre-video gate; earlier image stages retain direct-image plus human review. No model is guaranteed to catch every anatomy error, and a short clip or limb instruction cannot guarantee correct motion.

## Shared preview and export

`node runner.mjs preview --run /absolute/run` prepares the approved edit and serves a private localhost Remotion Player. Leave that process running while reviewing the composition. `render` uses the same scene payload and `RemotionAdScene → AdRenderSurface → memoir-film` path. Preview never changes approvals or invokes media providers. The downloadable archive ships the compiled renderer with a checked inventory; no application checkout is needed to operate it. Maintainers building from the Wiggly source checkout run `npm run build:renderer` before `pack:kit`. Browser setup may download Chrome Headless Shell; alternatively set `MEMOIR_BROWSER_EXECUTABLE` to a supported installed Chrome executable.

This adds the reusable format module and local composition preview, not a new /create page or a full editing UI. The existing approval state remains authoritative. Old FFmpeg-film manifests cannot be finalized under the new renderer contract without reopening the approved edit and reviewing the new render.

## Built-in local Codex workers

`crew-start --model gpt-5.6-sol --message "<actual human authorization>" --run /absolute/run` provisions durable role threads and binds them to SQLite. `drive-codex --max-tasks 8 --run /absolute/run` resumes actual workers through the supported app-server interface and stops at approval, qualification and production boundaries. No media generation is submitted by this dispatcher. The operator chose GPT-5.6 Sol; unavailable models are not silently substituted. See SKILL.md for setup, scope and version checks. Gemini listening/video observations and independent Cartesia batch STT are connected; calibrated speaker comparison and real reviewer qualification remain pending.

`check-provider --provider <service> --secrets /absolute/operator-repo/secrets.env` checks authenticated metadata with documented GETs only; it proves no billing, generation entitlement or creative quality. `present --run /absolute/run` returns the current verified, reviewed deliverable for chat, including four separate narration players. Neither command approves or generates anything. The [ChatGPT-plan inference limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations) confirm that native audio/video input is unavailable on this route.

The operator selected **Gemini 3.8 Flash** for media perception on October 2, 2026. Local Codex commands now connect `listenAudio` and `watchVideo` to that exact model through the scoped broker. GPT-5.6 Sol remains the configured crew worker; Gemini supplies actual media observations, not human approval. Supply the canonical `--secrets /absolute/operator-repo/secrets.env` containing `GEMINI_API_KEY`. Review inference is separately billed; `drive-codex`/`work-codex` require an explicit bounded `--review-calls N` (0–32 new review attempts per invocation, default 0). No review inference runs merely by starting or refreshing a crew. Check exact model access with `check-provider --provider gemini` first.

Video uses static sampling at min(measured source FPS, 4), high resolution and current scoped reference images/context; this requests dense whole-clip coverage without claiming perfect defect detection. Audio uses the original audio file; a video's audio is extracted to mono 48kHz PCM for separate listening. Large individual media files use the Files API with retained upload receipts; an aggregate inline request exceeding the safe 19 MiB bound stops rather than discarding references. Provider uploads are retained remotely according to Google's Files API lifetime; local run receipts remain private. Complete reports are hash-bound and reused; unknown uploads/inference are never automatically repeated. API failures terminate dispatch without model fallback. Before media approval in supervised mode, an intentional `crew-refresh --message "<actual human instruction>"` rebinds the same workers and reopens changed reviewer qualification/dependencies; never reset the run. Independent STT remains mandatory. Speaker comparison and human-labelled qualification are deferred in supervised mode and mandatory in qualified mode. This connection is implemented and mock-tested, not production-qualified.

**Independent transcription:** `--transcription-calls N` on local Codex dispatch allows 0–32 new Cartesia batch STT attempts, default 0. This separate cap does not authorize narration/video generation. The adapter sends actual audio plus the locked voice-sample language to Ink-Whisper (`POST /stt`, API version 2026-08-14), without script hints, and retains word timestamps/provider receipts. Exact task/hash/language/profile results recover offline; unknown requests stop without retry. Model/tool changes require explicit crew refresh and renewed qualification. See [Cartesia batch STT](https://docs.cartesia.ai/api-reference/stt/transcribe). No speaker score or human label is supplied by transcription.

## Runtime-loaded studio instructions

`studio.json` is the maintained configuration: named-role model defaults, permitted tool subsets, generation services, maximum retry limits and a $0 starting spend ceiling. Native workers default to GPT 5.6 Sol. Cartesia, Muse, Mini/480p and Gemini/4 FPS remain the selected services; unsupported provider substitutions fail validation. Actual account estimates and human-approved spend ceilings remain project records, not permission granted by this file. Explicit human model overrides are recorded in the crew binding.

Each named person has `crew/<name>/SKILL.md`; Pia’s one file covers sheet and background prompting while retaining the existing two distinct role bindings. Sage, Ava and Vera receive separate text/audio/visual rubrics in `evaluation/rubrics/`. Writers receive their skill and agreed runtime criteria; private reviewer procedures are not loaded into writing tasks. Recipes are attached only at their relevant prompt stages. Max plans Cartesia clone/audition/narration and other provider requests; the guarded runtime executes them.

New projects snapshot the exact config, skill/rubric/recipe/communication bodies and hashes in SQLite at initialization. Dispatch validates the current task and its artifact versions before sending a verified input checklist, current source text, approved dependencies and scoped media hashes to the assigned worker. Edits to template files affect future projects unless the human explicitly invokes the restricted writing-refresh exception described below. Actual models, human budgets, approvals and jobs stay authoritative in SQLite. Snapshots preserve instructions; they do not freeze installed code or media/tool capabilities. A changed host/tool profile still stops for explicit reconfiguration under the existing rules.

`orchestrator-voice.md` is loaded into status, work and presentation packets for the operating host chat. It calls for a brief friendly-producer update: current stage, what happened, next decision. The runner supplies a concise factual stage/decision summary without another narrator-model request. Reviewer evidence routes back to the responsible author; reviewers cannot call generation or authorize spend.

Projects predating this bundle retain the legacy instruction/provider path and are not silently migrated. A human `upgrade-studio` event can adopt current files only on a pristine project, before artifacts/jobs/crew exist. After work starts, `refresh-writing-instructions` may explicitly update only Leo’s skill and the text rubric while the script is unapproved and before any media jobs; it forces review again and preserves approved answers and earlier verdicts. Changes to config, models, tools, recipes or other instructions require a separate new project. Approvals are never silently migrated. Keep the compatible package for historical host/tool bindings. `recipe` and `background-recipe` display current template recipes; active tasks carry their project-pinned recipe instead.

Run `node --test tests/studio-instructions.test.mjs` for the snapshot/edit/restart, handoff/refusal, tool-boundary and rejection-loop checks. These are isolated mechanics, not media-quality certification.
