# Tutorial grammar distilled from Animal Conversations

## Proven in the recovered workflow

1. Proof first: open with the finished format and a credible demand signal.
2. Promise: say what the format does and what the user will receive.
3. Handoff: show the real Wiggly prompt copied into a computer-capable coding
   agent, not an invented chat transcript.
4. Preparation: show permitted source media, extraction, and transcription as
   host-agent work before the local format runtime.
5. Approval: show the timed speaker plan and require review of every beat,
   overlap, caption owner, and permission.
6. Replacement value: explain which separate image/video/editor steps the
   packaged Wiggly workflow removes.
7. Render and inspect: show the local render, contact sheet, MP4, and honest
   quality receipt.
8. Close: repeat the beginner checklist, cost, limits, and the next action.

## Format-specific facts that must remain labeled

Animal Conversations uses a recurring Dog/Bunny cast, packaged backgrounds,
cameras, and supplied creator audio. Those are not universal Tutorial Video
requirements. A new tutorial must declare its own source format, assets,
permissions, and runtime contract.

## Still requires human judgment

Caption readability, narration intelligibility, source permissions, and whether
the final tutorial is understandable to a new user require direct review. A
passing `ffprobe` check is necessary but not sufficient.
